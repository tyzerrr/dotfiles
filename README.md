# dotfiles

English | [日本語](README.ja.md)

macOS dotfiles. Clone the repository to `~/dotfiles`, and nix-darwin + home-manager put everything in place under `~/.config` and elsewhere.

Configs that are not converted to Nix, such as the Neovim Lua config, are still put in place by home-manager.

## Layout

```text
nix/
  flake.nix          nix-darwin + home-manager flake (profile = macOS user name)
  darwin.nix         nix-darwin settings shared by every machine (Homebrew, launchd agents)
  hosts/<user>.nix   per-machine nix-darwin settings (extra Homebrew packages, system.defaults)
  home.nix           home-manager entry point and package list
  home/              one home-manager module per tool
  pkgs/ overlays/    custom packages
  Makefile           commands to apply, build and roll back
nvim/ kitty/ wezterm/ sketchybar/ ...   configs that stay in their native format
```

A profile is the macOS user name: `araki` is the personal machine and `t-b-araki` is the work machine.

Each config is handled in one of three ways.

| How | What | When edits take effect |
| --- | --- | --- |
| Generated by Nix | zsh, oh-my-posh, git, tmux, ghostty, aerospace, gwq, cmux, borders, helm, the Homebrew trust list, macOS defaults | after `make switch` |
| Copied to the Nix store | sketchybar, wezterm, Claude Code agents/commands/skills, helper scripts for tmux and OmniWM | after `make switch` |
| Linked to the repository (`mkOutOfStoreSymlink`) | nvim, karabiner, kitty, OmniWM `settings.toml`, Claude Code `settings.json` / `mcp.json` / `CLAUDE.md` | immediately (the apps also write to these files) |

Linked configs are the files inside `~/dotfiles` themselves, so changes an app makes show up in `git diff`.

## How to apply

### Set up a new Mac

1. Install Nix with the Determinate Nix Installer.

   ```sh
   curl --proto '=https' --tlsv1.2 -sSf -L https://install.determinate.systems/nix | sh -s -- install
   ```

   nix-darwin is configured with `nix.enable = false`, so the Nix daemon and `/etc/nix/nix.conf` are left to the Determinate Nix Installer.

2. Install Homebrew: <https://brew.sh>

   Anything not in nixpkgs (`ghostty`, `mactex`, `sf-symbols`, `socket_vmnet`, ...) is installed through Homebrew, declared in `nix/darwin.nix` and `nix/hosts/<user>.nix`.

3. Clone to `~/dotfiles`. The location is fixed (`dotfilesDirOf` in `nix/flake.nix`).

   ```sh
   git clone git@github.com:tyzerrr/dotfiles.git ~/dotfiles
   ```

4. Apply. The profile defaults to the current user name (`$USER`). You will be asked for your sudo password.

   ```sh
   cd ~/dotfiles/nix
   make switch                    # profile of the current user
   make switch PROFILE=t-b-araki  # a specific profile
   ```

5. Open a new terminal (the zsh config only applies to new shells).

6. Go through [Check after applying](#check-after-applying).

`make switch` does the following:

- checks that the Determinate Nix Installer is installed
- checks that the repository is at `~/dotfiles`
- checks that the old `~/.config` checkout has no uncommitted changes left
- on the first run only, moves the shell init files nix-darwin manages to `*.before-nix-darwin` (`/etc/bashrc`, `/etc/zshrc`)
- applies nix-darwin and home-manager together with `darwin-rebuild switch`. If `darwin-rebuild` is not on `PATH` yet, it runs the nix-darwin version pinned in `flake.lock` through `nix run`

When a file already exists where home-manager wants to put one, the existing file is moved to `<name>.before-hm` first.

### Migrate from ~/.config

This repository used to be cloned directly into `~/.config`. home-manager cannot manage the same location it links from, so the repository moves to `~/dotfiles`.

1. Commit and push any uncommitted changes in `~/.config`. `make switch` stops if any are left.

   ```sh
   git -C ~/.config status
   ```

2. Clone to `~/dotfiles` and apply.

   ```sh
   git clone git@github.com:tyzerrr/dotfiles.git ~/dotfiles
   cd ~/dotfiles/nix
   make switch
   ```

3. Once everything works in a new terminal, move `~/.config/.git` out of the way (`~/.config` is no longer a repository).

   ```sh
   mv ~/.config/.git ~/.config.git.bak
   ```

4. Review the `*.before-hm` backups and clean them up if you no longer need them.

   ```sh
   find ~/.config ~/.claude/ ~ -maxdepth 3 -name '*.before-hm' 2>/dev/null
   ```

### Check after applying

Commands installed by Nix resolve from `~/.nix-profile` first. Homebrew or MacPorts copies may follow; only the first line matters.

```sh
which -a kubectl cmake emacs codex
```

```text
/Users/<you>/.nix-profile/bin/kubectl
/opt/homebrew/bin/kubectl
/Users/<you>/.nix-profile/bin/cmake
/opt/homebrew/bin/cmake
/Users/<you>/.nix-profile/bin/emacs
/Users/<you>/.nix-profile/bin/codex
```

GUI apps installed by Nix are in `~/Applications/Home Manager Apps`.

```sh
ls ~/Applications/"Home Manager Apps"
```

```text
AeroSpace.app  Emacs.app  OmniWM.app  pinentry-mac.app  TemporaryWindow.app  WezTerm.app
```

The launchd agents (AeroSpace and the OmniWM border-refresh watcher) are running. The first column is a PID, and the second is the last exit status, which should be `0`.

```sh
launchctl list | grep -E 'aerospace|omniwm'
```

```text
77548   0       org.nix-community.home.aerospace
61977   0       org.nixos.omniwm-border-refresh
```

Linked configs point into `~/dotfiles`. A plain `readlink` stops at the intermediate `/nix/store/...-home-manager-files/...` link, so use `-f` to follow the chain.

```sh
readlink -f ~/.config/nvim ~/.config/karabiner ~/.claude/settings.json
```

```text
/Users/<you>/dotfiles/nvim
/Users/<you>/dotfiles/karabiner
/Users/<you>/dotfiles/.claude/settings.json
```

If a path ends in `/nix/store/...` instead, that file is a store copy, not a link to the repository.

Accessibility permissions for AeroSpace, OmniWM and Karabiner-Elements cannot be declared. Grant them in System Settings → Privacy & Security → Accessibility on the first run and again after a Nix-installed app is updated.

## Day-to-day operations

```sh
cd ~/dotfiles/nix
make build                  # build without applying (output in ./result)
make switch                 # apply
make rollback               # go back to the previous generation
make generations            # list generations
make update                 # update flake.lock
make switch UPDATE_LOCK=1   # apply while allowing flake.lock updates
```

To change a setting:

1. `git pull` to get the latest main
2. Edit the config
3. `make build` to check that it builds
4. `make switch` to apply (linked configs already took effect when you saved them)
5. Commit and push

`make switch` passes `--no-update-lock-file` by default, so it fails instead of silently changing `flake.lock` on each machine. Update the lock on one machine with `make update`, commit it, then pull and `make switch` on the others.

## Adding or changing settings

- Tool config: create `nix/home/<tool>.nix` and add it to `imports` in `nix/home.nix`
- Packages: `home.packages` in `nix/home.nix`
- Homebrew-only software: `nix/darwin.nix` for every machine, `nix/hosts/<user>.nix` for one machine
- Helm repositories: `nix/home/helm.nix` (`helm repo add` fails because the file is read-only)
- macOS defaults: `system.defaults` in `nix/hosts/<user>.nix`

New files under `nix/home/` and elsewhere are invisible to the flake until you `git add` them.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `error: this repository must be cloned to ~/dotfiles` | Clone the repository to `~/dotfiles` and run `make switch` there |
| `error: ~/.config still has uncommitted changes in the old dotfiles checkout` | Commit and push the changes in `~/.config`, pull in `~/dotfiles`, then run it again |
| A config file seems to be gone after `make switch` | It was moved to `<name>.before-hm` |
| The window manager or another app ignores input | Grant the Accessibility permission again |
| Something broke after applying | `make rollback` to go back to the previous generation |
| A newly created `.nix` file is not found | `git add` it and run again |

## CI

`.github/workflows/ci.yml` checks every pull request:

- builds `darwinConfigurations.<profile>.system` for both profiles on a macOS runner (without activating)
- `nix flake check`
- gitleaks secret scan over the full history (configured in `.gitleaks.toml`)
